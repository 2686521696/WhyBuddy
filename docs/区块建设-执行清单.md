## ①b `targets` 显式连线 + Gate 四条

**参照**

| 仓库 | 路径 | 看什么 |
|---|---|---|
| nocobase | `packages/core/client/src/schema-settings/SchemaSettingsConnectDataBlocks.tsx` | **核心**。`targets.push({uid})` → `x-filter-targets`；`isSameCollection` 判同表；跨表要选关联字段 |
| nocobase | `packages/core/client/src/modules/blocks/filter-blocks/form/createFilterFormBlockSchema.ts` | 筛选区块是**顶层 CardItem**，`x-filter-targets: []` 是它自己的属性——证明不是套娃 |
| nocobase | `packages/core/client/src/modules/blocks/filter-blocks/form/filterFormBlockSettings.ts` | `connectDataBlocks` 作为一个区块设置项 |

**做**

1. `filter`/`action` 族的 `bindingSchema` 加 `targets: string[]`
2. `page_assembler.gate()` 补四条：
   - `target-missing` 目标不在这一页
   - `target-not-data` 目标不是 data 族
   - `target-entity-mismatch` 两者绑的实体不同
   - `filter-after-target` filter 族所在区域排在目标区域**之后**（先读内容再筛）
3. `filterState` / `selection` 从页面级一坨改成**按 target 分开存**

**修掉的真 bug**：`ComponentsLibraryPage.tsx` 的 `visibleRows` 对页面上所有实体
套同一份 `enumFilters`，只按字段名匹配。一页两张表都有 `status` 就互相干扰。

**验收**：造一页两张表（订单 + 客户，都有 status），筛一个另一个不动。

   propsSchema + bindingSchema(含 targets) + events
3. **落渲染器** —— 用我们的基础组件重写
4. **记来源** —— `source: { repo, path }`
5. **补用例** —— 钉住读到的边界情况（**这是搬运的真正产出**）
